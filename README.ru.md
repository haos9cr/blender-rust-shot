# Rust Shot — камера для демок Rust в Blender

[English version](README.md)

Аддон для Blender, который позволяет анимировать пролёты камеры для демок **Rust** и проигрывать их в игре.

В игре дебаг-камерой демки можно управлять только вручную (WASD + мышь), а полёт записывается в файл `.shot`.
Аддон читает и пишет этот формат. Можно строить плавные и точные пролёты в Blender (пути, констрейнты,
сглаживание, перевод фокуса) и отправлять их обратно в игру.

- Импорт любого `.shot` как анимированной камеры: позиция, вращение, FOV, глубина резкости
- Экспорт анимации любой камеры в `.shot`, который проигрывает игра
- Все записанные на сегодня файлы пересобираются байт-в-байт
- Работает и без Blender: маленькая консольная утилита переводит `.shot` ⇄ JSON

> Неофициальный инструмент. Не связан с Facepunch Studios.
> Формат `.shot` восстановлен вручную и может измениться с обновлениями игры.

## Установка

1. Скачайте `rust_shot.py`.
2. Blender → **Edit → Preferences → Add-ons → Install from Disk…** (в старых версиях — **Install…**) → выберите `rust_shot.py` → включите **Rust camera shot (.shot)**.
3. В 3D-виде откройте сайдбар (**N**) → вкладка **Rust Shot**.

Проверено на Blender 5.2. Код рассчитан на 3.0+, включая новый API анимации 4.4+/5.x.

## Использование

### Импорт
**Панель Rust Shot → Import Rust shot** (или **File → Import → Rust camera shot**).
В настройках импорта выберите FPS сцены (по умолчанию 60). Ключи расставляются так, чтобы скорость в реальном времени сохранилась.

Импортированная камера помнит путь к демке, время старта в демке, папку шота и значения DOF.
Когда камера выделена, всё это можно поменять в панели.

### Экспорт
Настройте экспорт в панели и нажмите **Export to Shots folder** (или **File → Export → Rust camera shot**).

| Настройка | Что делает |
|---|---|
| **Camera** | Активная/выделенная камера, камера сцены, выбор из списка или **все выделенные камеры** (каждая в свой файл с её именем) |
| **Range** | Диапазон сцены, preview-диапазон, ключи самой камеры или свои кадры |
| **Time base** | FPS сцены (как проигрывает Blender) или свой FPS |
| **Speed** | Скорость в игре: `2` — вдвое быстрее, `0.5` — замедленная съёмка |
| **Samples / sec** | Сколько ключей в секунду писать (сама игра пишет около 45). Не зависит от FPS сцены, промежуточные кадры считаются |
| **FOV** | С камеры (анимируется) или постоянное значение |
| **DOF** | Писать глубину резкости, если она включена на камере / всегда / никогда |
| **Shots folder**, **File name** | Куда сохраняет быстрый экспорт; пустое имя — имя камеры |

Перед экспортом панель показывает, **сколько секунд шот будет идти в игре и сколько в нём ключей**.

Камеру можно двигать как угодно: ключи, Follow Path, Track To, родители, драйверы.
В файл записывается итоговое положение в мире.

### Время и FPS
Время в шоте = `(кадр − начало диапазона) / FPS / speed`. Если поменять FPS сцены *после* анимации,
ключи остаются на тех же кадрах, и в игре шот пойдёт быстрее или медленнее. Аддон запоминает,
при каком FPS сделана анимация, и предупреждает, если FPS не совпадает:

- **Rescale keys (keep speed)** растягивает ключи, диапазон кадров и маркеры, сохраняя скорость в секундах.
- **Animation is fine at current FPS** оставляет новую скорость.
- **Change FPS (keep timing)** меняет FPS и сразу пересчитывает ключи.

### Глубина резкости
Треки DOF пишутся, только если при записи в игре включена запись DOF (или при экспорте стоит **DOF = Always**).

| Переменная игры | Blender |
|---|---|
| `graphics.dof_focus_dist` | Camera → Depth of Field → Focus Distance (или расстояние до **Focus Object** вдоль взгляда) |
| `graphics.dof_aper` | Camera → Depth of Field → F-Stop |
| `graphics.dof_blur` | **DOF blur** в панели Rust Shot (анимируется) |

## Система координат

В Rust координаты Unity: X вправо, Y вверх, Z вперёд, левая система. В Blender Z вверх, правая система.

- Позиция: Blender `(x, y, z)` = Unity `(x, z, y)`. Единицы — метры в обоих.
- Вращение: `матрица_камеры_blender = S · R_unity · diag(1, 1, −1)`, где `S` переставляет Y и Z.
  Дополнительный поворот нужен потому, что камера Unity смотрит вдоль +Z, а камера Blender — вдоль −Z.
- Углы дебаг-камеры — это Unity `Quaternion.Euler(x, y, z)` (сначала Z, потом X, потом Y).
- FOV вертикальный, в градусах. У импортированных камер вертикальная подгонка сенсора.

## Консоль (без Blender)

```
python rust_shot.py decode  in.shot  out.json   # посмотреть / поправить как JSON
python rust_shot.py encode  in.json  out.shot
python rust_shot.py roundtrip a.shot b.shot ...  # проверка пересборки байт-в-байт
python tests/test_roundtrip.py                   # проверка всех файлов в samples/
```

Функции можно импортировать и из своего кода: `rust_shot.load(path)`, `rust_shot.save(shot, path)`,
`rust_shot.decode(bytes)`, `rust_shot.encode(dict)`.

## Формат файла

Подробно — в [docs/FORMAT.md](docs/FORMAT.md). Коротко: protobuf-сообщение с именем, путём к демке,
временем старта и длительностью, плюс треки ключей: позиция, вращение (кватернион), FOV и при желании DOF.

## Примеры

`samples/test_orbit.shot` — 10-секундный облёт вокруг начала координат, сделанный в Blender этим аддоном;
проверен в игре. Свои шоты, записанные дебаг-камерой, можно класть в `samples/`:
`tests/test_roundtrip.py` проверяет все файлы в этой папке.

## Известные ограничения

- Поле 12 не расшифровано: это всегда один и тот же маленький блок, он копируется как есть.
- Игра пишет дистанцию фокуса уже сглаженной. Сглаживает ли она её ещё раз при проигрывании — неизвестно.
- Поддерживается только формат шотов дебаг-камеры. Загрузка карты и самой демки — отдельный проект.
